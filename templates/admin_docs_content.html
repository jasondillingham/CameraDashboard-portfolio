How Streams Work
1
Stream Registration (Startup)

When the app starts, it registers RTSP streams with go2rtc for every NVR channel. Each channel gets two streams:

  • Main (HD): rtsp://user:pass@IP:554/Streaming/Channels/{ch}01
  • Sub (SD): rtsp://user:pass@IP:554/Streaming/Channels/{ch}02

H.265 streams get an automatic FFmpeg transcoding fallback to H.264 for browser compatibility.

2
Live Viewing (WebRTC)

The browser uses go2rtc's <video-stream> custom element with a WebSocket connection:

<video-stream src="go2rtc/api/ws?src={streamName}" mode="webrtc,mse,hls">

go2rtc handles the RTSP → WebRTC/MSE protocol conversion. All video processing happens on the go2rtc server — the user's browser just receives the decoded stream.

3
Recording Playback

Playback uses Hikvision's RTSP playback URLs with time range parameters:

rtsp://user:pass@IP:554/Streaming/tracks/{ch}01?starttime=...&endtime=...

A temporary stream is registered with go2rtc (named playback_{sessionID}) and delivered to the browser via WebRTC, same as live.

Sessions auto-cleanup after 5 minutes of inactivity. Max 4 playback sessions per NVR (LRU eviction).

4
Video Export (MP4 Download)

Export uses FFmpeg on the server to read the RTSP playback URL and transcode to MP4:

ffmpeg -rtsp_transport tcp -i {rtspURL} -c:v libx264 -preset fast -crf 23 -c:a aac -movflags +faststart output.mp4

Progress is tracked in real-time. Exports auto-delete after 30 minutes.

Stream Naming Convention
Type Pattern Example

Bandwidth Optimization
  • Grid dashboards use sub-streams (SD) to reduce bandwidth across multiple cameras
  • Live view defaults to sub-stream with an HD toggle button
  • Snapshots prefer sub-streams for faster capture
  • Exports respect the user's quality selection (SD or HD)
Estimated Max Concurrent Streams

go2rtc relays RTSP streams via WebRTC without transcoding (unless H.265 → H.264 is needed). Capacity depends on the server's network bandwidth and CPU.

Stream Type Per-Stream BW Max @ 100 Mbps Max @ 1 Gbps
Sub (SD) ~0.5–1 Mbps ~100 streams ~500+ streams
Main (HD) ~4–8 Mbps ~12–25 streams ~125 streams
H.265 → H.264 transcode ~1 CPU core each Limited by CPU cores (e.g., 8 cores ≈ 8 transcodes)
